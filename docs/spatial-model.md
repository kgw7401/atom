## 결정 1 — 위에서 본 링으로 투영한다

영상에서 뽑은 데이터를 **링을 바로 위에서 내려다본 2D 좌표**로 바꾼다.
지표를 따로따로 계산하지 않고, 먼저 이 표현을 만든 다음 거기서 전부 유도한다.

### 왜 이 방식인가

**복싱의 공간이 실제로 2D다.** 두 선수 다 바닥 위에 서 있다. 높이는 거의 무의미하다.
2D 평면은 정보를 버리는 게 아니라 **딱 맞는 표현**이다. 축구 분석이 같은 이유로
top-down 을 쓴다.

**네 층이 하나의 표현에 전부 담긴다.**

| 층 | 위에서 본 그림에서 |
|---|---|
| 거리 | 두 점 사이 간격 |
| 움직임 | 점의 시간 변화 |
| 링 | 점의 절대 위치 |
| 각도 | 점에 붙은 화살표 |

따로 계산할 게 없다. 좌표 하나에서 전부 나온다.

**눈으로 검증된다.** 1단계에서 확인용 영상을 눈으로 보는 것이 가장 강력한 검증
수단이었다. 위에서 본 그림은 그 자체가 검증 도구다. 두 점이 링 안에서 말이 되게
움직이는지 보면 바로 안다.

**도메인 언어와 일치한다.** "코너로 몬다", "중앙을 잡는다", "부채꼴로 좁힌다" —
전부 위에서 본 그림이다. 코치가 화이트보드에 그리는 게 top-down 이다.
표현이 도메인 사고방식과 같으면 결과를 해석하기 쉽다.

### 검토한 대안

| 방식 | 왜 안 쓰나 |
|---|---|
| 화면 좌표 그대로 | 원근 왜곡. 카메라 각도가 다르면 **영상 간 비교가 안 된다** |
| 거리 스칼라 하나만 | "어디서" 그 거리였는지가 사라진다. 링 층이 통째로 날아간다 |
| 3D 자세 복원 | 카메라 한 대로는 깊이가 불안정하고, **필요 없는 정보가 대부분**이다. 팔꿈치 각도는 공간 분석에 쓸 데가 없다 |
| 영상을 통째로 학습 | 라벨이 수천 개 필요하고, **왜 그렇게 판단했는지 설명이 안 된다.** 목적이 이해인데 이해를 주지 않는다 |

### top-down 이 못 담는 것

동의만 하고 넘어가지 않기 위해 한계도 적어둔다. 셋 다 **top-down 을 대체하는 게
아니라 위에 얹는 것들**이다.

| 한계 | 대응 |
|---|---|
| 높이 — 더킹·슬리핑이 안 보인다 | 점에 "지금 얼마나 낮은지" 를 값으로 붙인다 |
| 팔 상태 — 뻗은 팔과 접은 팔은 사거리가 다르다 | 마찬가지로 값으로 붙인다 |
| 겹칠 때 부정확 — 발 위치가 흔들린다 | 신뢰도를 같이 기록한다. 1단계에서 이미 하고 있다 |

## 결정 2 — 선수를 원 두 개로 표현한다

각 선수는 점 하나가 아니라 **동심원 두 개**다.

```
        ╭─────────────╮
       ╱   ╭───────╮   ╲
      │   │  몸 원  │    │  ← 사거리 원
      │    ╰───────╯    │
       ╲               ╱
        ╰─────────────╯
```

| 원 | 뜻 |
|---|---|
| **몸 원** | 몸이 차지하는 공간 |
| **사거리 원** | 팔을 뻗어 닿는 범위 |

### 5단계 거리가 원 관계에서 자동으로 나온다

`docs/spatial-primer.md` 2장의 거리 5단계를 **주관적 판단 없이** 얻을 수 있다.

```
① 아웃 오브 레인지         ② 엣지 오브 레인지
   (  A  )    (  B  )        (  A  )(  B  )
   사거리 원이 안 닿음        사거리 원이 딱 닿음

③ 롱 레인지                ④ 미드 · 클로스
   (  A ( ) B  )              ( A(X)B )
   사거리 원이 상대 몸에 닿음   몸 원까지 가까움
```

| 단계 | 원의 관계 |
|---|---|
| 아웃 오브 레인지 | 사거리 원끼리 안 닿음 |
| **엣지 오브 레인지** | **사거리 원이 서로 닿는 순간** |
| 롱 레인지 | 내 사거리 원이 상대 **몸 원**에 닿음 |
| 미드 레인지 | 겹침이 커짐 |
| 클로스 레인지 | 몸 원이 거의 닿음 |

**이게 중요한 이유**: 1단계에서 밀착 경계를 0.65m 로 정할 때는 사진을 보고
사람이 판단했다. 주관적이었다. 원 방식은 **"닿나 안 닿나"** 라는 객관적 기준을 준다.

### 리치 차이가 자동으로 담긴다

두 선수의 사거리 원 크기가 다르면 **한쪽만 닿는 구간**이 생긴다.

```
     ┌────── A의 사거리 (김) ──────┐
   ( A )                        ( B )
              └── B의 사거리 (짧음) ──┘
     └────┘
      A만 닿는 구간
```

primer 1장에서 말한 그 구간이다. 리치가 짧은 쪽에게는 지옥이고, 긴 쪽은 상대를
여기 붙잡아두려 한다. **거리 하나만 재서는 절대 안 나오는 정보다.**

여기서 바로 나오는 스탯 세 개:

| 스탯 | 정의 |
|---|---|
| **일방 우위 시간** | 내 사거리 안 + 상대 사거리 밖 |
| **동시 위험 시간** | 둘 다 닿음 |
| **안전 시간** | 둘 다 못 닿음 |

이 셋만으로 스타일이 상당 부분 설명된다. 아웃복서는 일방 우위 시간이 길고,
스워머는 동시 위험 구간을 통과해 들어가는 사람이다.

### 원은 앞쪽으로 치우친다

복서는 등 뒤를 때리지 못한다. 실제 사거리는 정면 쪽으로 쏠려 있다.

```
   정면 →
     (  (    ))
   뒤는 짧고 앞은 길다
```

원을 정면 방향으로 치우친 모양으로 두면 **각도가 같은 그림에 들어온다.**
"같은 거리인데 옆을 잡혔다" 가 **원이 안 겹치는 상태**로 표현된다.
각도가 별도 층이 아니게 된다.

### 사거리 반경을 어떻게 정하나

| 방법 | 장점 | 단점 |
|---|---|---|
| 키에서 비율로 추정 | 항상 계산됨 | 사람마다 팔 비율이 다름 |
| 자세 모델의 어깨~손목 (매 프레임) | 실측값 | 팔 접으면 짧게 나오고, 카메라 쪽으로 뻗으면 왜곡 |
| **영상 전체에서 최대치** | **안정적. 선수별 상수가 됨** | 최대로 뻗은 순간이 영상에 있어야 함 |

**세 번째를 쓴다.** 자세 모델이 어깨·팔꿈치·손목을 주므로 계산은 쉽고,
스파링이면 최대로 뻗는 순간이 반드시 나온다.

> **나중에**: 잽 사거리와 훅 사거리는 다르다. 원이 여러 개여야 정확하다.
> 하지만 그건 2단계(펀치 검출)가 있어야 알 수 있다. 지금은 하나로 시작한다.

## 결정 3 — 데이터 형태

프레임마다, 선수마다 한 줄.

```
frame          프레임 번호
time_sec       시간
fighter        me / opponent

x, y           링 위 위치 (링 좌표)

body_r         몸 반경
```

**계산해서 얻는 것이지 따로 측정하는 게 아니다.**

## 결정 4 — 링 경계는 처음부터 넣는다

링 좌표를 만들려면 **화면 속 링의 네 모서리**가 필요하다.
이 대응만 알면 화면의 아무 점이나 링 좌표로 바꿀 수 있다 (호모그래피).

즉 **"링을 인식한다" = "캔버스 네 모서리를 찾는다"** 이다.

### 이건 이미 풀린 문제다

축구 방송 분석에서 **sports field registration(경기장 정합)** 이라는 이름으로
잘 정리돼 있다.

| 자료 | 내용 |
|---|---|
| [Roboflow 튜토리얼](https://blog.roboflow.com/camera-calibration-sports-computer-vision/) | YOLO 키포인트로 표식을 찾아 호모그래피 계산. 가장 실용적 |
| [TVCalib](https://arxiv.org/abs/2207.11709) | 연구급. 카메라 자세와 초점거리를 같이 추정 |
| [Football-PitchVision](https://github.com/DesusLove/Football-PitchVision) | 검출 → 추적 → 호모그래피 → top-down 레이더 전체 파이프라인 |
| [SoccerNet Game State Reconstruction](https://arxiv.org/pdf/2404.11335) | 미니맵 복원을 벤치마크로 정의 |

축구용이라 모델은 그대로 못 쓰지만 **파이프라인 구조가 같다.**

### 복싱 링이 오히려 유리하다

| | 축구장 | 복싱 링 |
|---|---|---|
| 표식 | 선·원·박스, 많지만 복잡 | **정사각형 하나** |
| 필요한 점 | 여러 개 조합 | **모서리 4개면 끝** |
| 가려짐 | 선수가 선을 가림 | **로프는 항상 선수 앞에 있다** |

### 화면 밖 모서리 문제는 풀린다

우리 영상(`IMG_0711`)은 링 앞쪽 두 모서리가 화면 밖이라 막혀 있었다.

**모서리를 직접 찾는 대신 로프·캔버스 경계선을 찾아 연장한다.**
두 선이 만나는 점이 모서리이고, 그 점이 화면 밖이어도 계산으로 구할 수 있다.

```
   경계선 1 ─────────────╲
                          ╲
                           ╳  ← 화면 밖 모서리도 구해짐
   경계선 2 ──────────────╱
```

**다시 찍지 않아도 3층이 열린다.**

### 난이도가 두 갈래로 갈린다

| | 고정 카메라 (우리 영상) | 중계 영상 |
|---|---|---|
| 모서리 찾기 | **영상당 한 번** | **매 프레임** |
| 방법 | 손으로 4점 | 자동 검출 모델 |
| 비용 | 몇 분 | 진짜 작업 |

카메라가 고정이면 링이 안 움직이므로 한 번 찍어두면 영상 전체에 쓴다.

**그래서 고정 카메라부터 한다.** 두 가지 위험을 분리하기 위해서다.

1. top-down 분석이 실제로 쓸모 있나?
2. 카메라 자동 정합이 되나?

고정 카메라에서는 1번만 검증하면 된다. 여기서 쓸모가 확인돼야 2번에 투자할
근거가 생긴다. 반대로 하면 자동 검출을 다 만들고 나서 분석이 별로일 수 있다.

**부수 효과**: 손으로 찍은 결과가 자동 검출의 **정답지**가 된다.
같은 영상에 자동 검출을 돌려 비교하면 정확도를 바로 잴 수 있다.

## 결정 5 — 스탯이 먼저, 분류는 나중

스타일 4분류를 목적지로 삼지 않는다. **스탯을 만드는 것이 목적**이고,
스타일 분류는 그 위에서 할 수 있는 여러 가지 중 하나다.

이유:

- 스탯이 있으면 스타일 분류도, 특정 라운드 분석도, 매치업 분석도, 본인 코칭도 된다
- **스탯은 하나씩 눈으로 검증할 수 있다.** 군집은 검증이 어렵다
- 야구 세이버메트릭스가 이 순서였다. 먼저 스탯을 만들고, 유형 논의는 그 다음이었다

### 나올 수 있는 스탯들

| 층 | 스탯 |
|---|---|
| 거리 | 5단계별 체류 시간, 일방 우위 / 동시 위험 / 안전 시간 |
| 움직임 | 접근 주도 비율, 후퇴 주도 비율, 전진·후퇴 시간 비 |
| 링 | 중앙 점유율, 로프·코너 압박 시간, 갈 수 있는 방향의 각도 범위 |
| 각도 | 각도 우위 시간, 피벗 빈도 |

### 링 4점을 찍지 않았다 — 소실점을 썼다

계획은 캔버스 네 모서리를 손으로 찍는 것이었다. 실제로는 못 했다.
왼쪽 코너 포스트 밑동은 배너에, 오른쪽은 쌓아둔 장비에 가려 정확히 짚을 수 없었다.

대신 **로프의 소실점**을 썼다. 로프는 실제로 평행하므로 화면에서 만나는 점이
소실점이고, 링은 정사각형이므로 두 방향이 직각이다. 그 두 사실만으로
초점거리와 지평선이 나온다. 모서리를 짚을 필요가 없다.

선수를 지운 배경 프레임(60장의 중앙값)에서 선분을 찾고 RANSAC 으로 소실점을 구했다.

| | 값 | 지지 선분 |
|---|---|---|
| 좌우 방향 소실점 | (-9356, 88) | 121/137 |
| 깊이 방향 소실점 | (1471, 73) | 15/15 |

### 앞의 보정이 틀려 있었다

| | 사람 키 기준 (이전) | 링 기준 (지금) |
|---|---|---|
| 초점거리 | 1280 (기종 명목값 **가정**) | **2249** (측정) |
| 지평선 y | 9 | **74** |
| 카메라 높이 | 2.18 m | 2.12 m |

**초점거리를 1.76배 틀리게 잡고 있었다.** 35mm 환산 42mm 로 나오는데,
줌으로 찍힌 영상이라 1x(24mm) 명목값이 맞지 않았던 것이다.

결과적으로 **깊이가 절반 이하로 눌려 있었다.** 링은 정사각형인데 선수 이동 범위가
좌우 3.58m × 앞뒤 1.55m 로 나왔다 (비율 0.43). 새 보정에서는 3.27 × 2.71m (비율 0.83)다.
1보다 작게 남는 것은 화면 아래가 잘려 링 앞쪽을 못 보기 때문이다.

**독립적인 검증도 통과했다.** 두 선수가 화면에서 좌우로 벌어져 있을 때의 거리는
초점거리와 무관하고, 앞뒤로 벌어져 있을 때는 초점거리에 비례한다. 복서는 카메라

완전히 다른 두 방법이 같은 값을 가리킨다.

### 이전에 "개선" 한 것이 사실은 개악이었다

### 사거리 반경

중앙값은 1.68m 다. 대부분의 시간을 사거리 밖에서 보낸다는 뜻이 된다.

원인은 원이 하나로는 부족하다는 것이다. primer 의 정의가 이미 그렇게 말하고 있다 —
**"엣지 오브 레인지 = 한 발 들어가면 닿는 경계"**. 즉 손만 뻗어 닿는 거리와

| 원 | 뜻 |
|---|---|

| 정지 사거리 | 발을 안 옮기고 닿는 범위 (지금 측정한 것) |
| **한 발 사거리** | 스텝을 밟아 닿는 범위 ← 아직 없다 |

한 발 사거리는 2단계(펀치 이벤트)가 있어야 제대로 잰다. 펀치가 실제로 닿은
순간의 거리 분포에서 역산하는 것이 옳다.

### 정면 방향 시계열 정리 (같은 날 추가)

화살표가 계속 떨고 방향이 자주 틀린다는 지적을 받고 다시 봤다. 프레임마다
따로 계산하면 두 가지 병이 섞인다.

| 병 | 원인 |
|---|---|
| 잡음 | 어깨 키포인트가 몇 픽셀 떨리면 각도가 크게 흔들린다 |
| 180도 반전 | 자세 모델이 좌우 어깨 라벨을 순간 바꿔치기하면 정면이 정반대가 된다 |

**세 번 실패하고 네 번째에 됐다.** 실패 기록을 남겨둔다.

| 시도 | 방법 | 결과 |
|---|---|---|
| 1차 | 시간 연속성으로 반전을 되돌림 | 잡음은 잡혔으나 **오차 33도 -> 60도**. 한 번 잘못 정한 부호가 구간 전체로 퍼짐 |
| 2차 | 축과 부호를 분리 (각도 2배 평균 + 창 다수결) | 정확도 복구, 그러나 **반전 60 -> 100회** |
| 3차 | 부호에 관성 추가 | **반전 218회로 악화** |
| 4차 | 절반으로 되돌리기 전에 각도를 이어붙임 | **전 지표 개선** |

3차에서 원인을 찾았다. 각도를 2배로 만들어 평균한 뒤 절반으로 되돌리면 결과가
(-90, 90] 에 갇힌다. 실제 방향이 그 경계를 지날 때마다 값이 180도씩 튀는데,
**회전이 아니라 표현의 문제였다.** 절반으로 되돌리기 전에 각도를 이어붙이면
(`np.unwrap`) 사라진다.

교훈: 1차 실패는 **연속성만으로는 "모델이 라벨을 뒤집었다" 와 "선수가 실제로
돌았다" 를 구분할 수 없다**는 것이다. 축(잘 측정됨)과 부호(가끔 뒤집힘)는
성질이 다르므로 따로 다뤄야 한다.

| | 흔들림(1프레임) | 반전 | 상대방향 오차 | 90도 이내 |
|---|---|---|---|---|
| 원본 | 3.9도 | 60회 | 33도 | 89% |
| 지금 | **1.3~1.5도** | **14~24회** | 29~35도 | **90%** |

### 오차 30도는 정상이다

"화살표가 거의 무조건 상대를 향해야 한다" 는 기대는 맞지 않는다.
**복서는 몸을 비스듬히(bladed) 틀고 선다.** 가슴이 향하는 방향은 상대 방향과

화살표가 항상 상대를 정확히 가리킨다면 오히려 측정이 잘못된 것이다.
또한 정면을 상대 방향으로 정의하면 "각도를 잡았나" 를 잴 수 없게 된다 —
항상 정면으로 나오기 때문이다.

감도를 보여주는 표**로 바꿨다.

| +0.4 m | 11% | 87% |
| +0.6 m | 25% | 71% |

이 표 자체가 **한 발 사거리가 반드시 필요하다는 증거**다.

**피벗** — 분당 1089회가 나왔다. 초당 18번이니 잡음을 센 것이다. 순간 각속도
임계값(120도/초)이 잡음 바닥(정면이 프레임당 1.3도 흔들리면 초당 78도)
바로 위였다. 짧은 창 동안 **한 방향으로 꾸준히 돈 양**을 보고 불응기를 두는
방식으로 바꾸니 분당 46~73회가 됐다.

### 각도는 이 카메라로 못 잰다 (2026-07-29)

"화살표가 계속 왔다갔다 한다" 는 지적을 받고 파고들었더니, 고칠 수 있는 버그가
아니라 **기하학적 한계**였다.

**먼저 내 진단이 틀렸다.** 어깨선을 지평선까지 연장하는 방식이 dy→0 에서 발산해
흔들린다고 보고 식을 바꿨는데, 두 식은 **같은 값**이었다 (차이 중앙값 0.0000도,
흔들림 3.82 vs 3.81도). 대수적으로 동일한 식은 입력 잡음을 똑같이 전달한다.
조건수는 부동소수점 정밀도의 문제이지 측정 잡음 민감도의 문제가 아니다.

**진짜 원인**: 어깨선이 화면에서 수평에 가까우면 3차원 방향이 원래 결정되지 않는다.
그리고 이 카메라 각도에서는 **71% 의 프레임이 그렇다** (신뢰도 중앙값 0.10).
카메라가 링을 얕은 각도로 내려다보고 복서의 어깨는 대체로 수평이기 때문이다.

신뢰도(어깨선 화면 기울기의 sin)로 거르면 값은 좋아진다.

| 신뢰도 하한 | 남는 프레임 | 상대향 오차 | 90도 이내 |
|---:|---:|---:|---:|
| 전체 | 99% | 33도 | 90% |
| 0.3 | 20% | 26도 | 96% |
| 0.5 | 11% | 26도 | 98% |

**하지만 두 선수가 동시에 신뢰할 만한 프레임은 3% 뿐이다** (0.2 x 0.2).
99초 중 3초다. 각도 스탯은 이 위에 세울 수 없다.

지금 한 처리:
- 각도 스탯은 신뢰도 0.3 이상 프레임만 쓰고, 커버리지를 함께 적는다
- top-down 영상에서 신뢰도가 낮으면 화살표를 흐리고 가늘게 그린다 —
  추측인 순간이 눈에 보이게

**주의**: 피벗은 이 필터와 상성이 나쁠 수 있다. 몸을 돌리는 동안 어깨선이
수평 구성을 지나가므로, 정작 피벗하는 순간이 걸러질 가능성이 있다.

**해결책은 촬영이다.** 카메라를 더 높이 올려 위에서 내려다볼수록 어깨선이
화면에서 기울어져 방향 정보가 살아난다. 링 전체가 나오는 화각(3층 문제)과
같은 방향의 처방이다.

### 아직 못 하는 것

- 거리 5단계 체류 시간 — 경계값 무효 + 한 발 사거리 없음
- 링 관련 (중앙 점유, 코너 압박) — 링 경계가 영상마다 다르다
- **각도 전반** — 두 선수 동시 신뢰 프레임이 3% (위 참고)

## 아직 안 된 것

- **링 크기가 영상마다 다르게 나온다** (위 참고). 로프나 코너 포스트 기반으로 바꿔야 한다
- **5단계 거리 구분을 검증하지 못했다.** 경계값이 무효가 된 데다, 한 발 사거리가
  없어서 원 관계로 단계를 나눌 수 없다
- **앞쪽 변은 추정값이다.** 정사각형 조건에서 나온 것이므로, 링 전체가 나오는
  화각으로 다시 찍으면 실측으로 검증할 수 있다
- **정면 오차 10%** — 어깨가 카메라 쪽으로 정렬된 순간. 신뢰도로 표시하면 좋겠다
- **사거리 반경이 영상 길이에 좌우된다** (위 참고)
