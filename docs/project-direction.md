# 프로젝트 방향: 개인 스파링 의사결정 분석

## 1. 한 문장 목표

복싱 스파링 영상을 AI가 분석해, 내가 압박 상황에서 **무엇을 보고 어떤 선택을 했는지** 이해하고 다음 라운드에서 실행할 수 있는 한 가지 행동 규칙으로 바꾸는 개인 훈련 시스템을 만든다.

현재 이 프로젝트의 첫 사용자는 나 자신이다. 서비스 출시, 사용자 확보, 논문 출판은 지금의 완료 조건이 아니다.

## 2. 출발점

내가 해결하려는 문제는 샌드백이나 셰도우에서 기술을 수행하지 못하는 문제가 아니라, 스파링에서 상대의 압박, 거리, 타이밍 앞에서 판단이 늦어지거나 멈추는 문제다.

따라서 첫 질문은 다음이다.

> AI가 스파링 영상에서 내가 실제로 판단을 놓친 장면을 시간 근거와 함께 찾아내고, 다음 라운드에서 시험할 수 있는 피드백으로 만들 수 있는가?

이 질문에 답하기 전에는 완전한 복싱 분석 모델, 자동 채점 시스템, 서비스 UI를 만들지 않는다.

## 3. 현재의 핵심 가설

초기 Gemini 분석은 압박을 받을 때의 직선 후퇴와 방어 뒤 멈춤을 후보 패턴으로 제시했다. 이것은 결론이 아니라 다음 스파링에서 검증할 가설이다.

```text
상대의 전진 압박
  -> 나는 방어하거나 뒤로 물러남
  -> 옆으로 빠지기, 반격, 클린치 같은 다음 선택이 늦어짐
  -> 로프 또는 코너에 갇히거나 수세가 길어짐
```

검증할 행동 규칙의 예시는 다음과 같다.

> 상대가 압박하며 들어오면 직선으로 계속 후퇴하지 않고, 비어 있는 쪽으로 한 번 피벗 또는 사이드스텝한다.

이 규칙이 좋은 기술인지보다, 내가 실제 라운드에서 기억하고 실행할 수 있는지가 먼저다.

## 4. 프로젝트의 반복 루프

```text
스파링 한 라운드 촬영
  -> AI가 의미 있는 공방과 후보 문제를 시간순으로 정리
  -> 내가 원본 영상으로 근거와 타임스탬프를 확인
  -> 반복 패턴 하나와 다음 라운드 규칙 하나를 선택
  -> 다음 스파링에서 그 규칙을 실행
  -> 실행 여부와 새로운 실패 장면을 다시 분석
```

좋은 결과물은 긴 코칭 리포트가 아니다. 다음 세 가지가 남으면 된다.

- 확인 가능한 타임스탬프와 시각적 근거
- 반복되는 의사결정 패턴 하나
- 다음 라운드에서 시험할 짧고 관찰 가능한 행동 규칙 하나

## 5. 분석 대상의 구분

샌드백/셰도우와 스파링을 하나의 문제로 취급하지 않는다.

| 모드 | 주된 질문 | 초기 피드백 단위 |
| --- | --- | --- |
| 스파링 | 상대의 행동을 보고 어떤 판단을 했는가? | 압박, 거리, 방어 뒤 선택, 탈출, 카운터 기회 |
| 샌드백/셰도우 | 계획한 기술을 어떻게 수행했는가? | 자세, 균형, 연계, 반복, 리듬 |

첫 번째 개발과 실험의 중심은 **스파링 모드**다. 드릴 모드는 나중에 스파링에서 발견한 문제를 연습하기 위한 보조 모드로 붙인다.

## 6. 현재 기술 전략: VLM-first

초기에는 새 복싱 모델을 학습하지 않는다. Gemini 같은 일반 영상 VLM을 사용해 먼저 다음을 검증한다.

```text
영상
  -> 의미 있는 공방 후보와 타임스탬프
  -> 보이는 사실 중심의 구조화된 관찰 JSON
  -> 반복 패턴과 다음 라운드 규칙
```

VLM의 역할은 우선 **코치가 아니라 관찰자**다. 모델은 보이는 행동, 거리 변화, 움직임을 정리하고, 명중 여부나 상대의 의도를 근거 없이 단정하지 않아야 한다.

Gemini 기본 영상 처리는 빠른 펀치 수준의 세부 동작을 놓칠 수 있다. 그래서 전체 라운드에서는 후보 구간 탐색을 맡기고, 중요한 장면은 5~15초 클립 또는 느린 클립으로 다시 확인한다. 정확한 펀치 종류나 판정은 현재 단계의 목표가 아니다.

## 7. 현재 구현 범위

`analyze_sparring.py`는 현재 다음을 수행한다.

1. 로컬 스파링 영상을 Gemini Files API에 업로드한다.
2. 파일이 `ACTIVE` 상태가 될 때까지 기다린다.
3. 나를 식별하는 설명과 함께 구조화된 스파링 분석을 요청한다.
4. 타임스탬프, 문제 유형, 시각적 근거, 확신도, 반복 패턴, 다음 라운드 규칙을 JSON으로 저장한다.
5. 기본값으로 원격 파일을 삭제한다.

출력 JSON은 모델의 판정문이 아니라, 내가 재생하며 확인할 **후보 관찰 기록**이다.

## 8. 다음 실험 프로토콜

### 촬영

- 2~3분의 스파링 한 라운드부터 시작한다.
- 두 선수의 발과 상체가 가능한 한 계속 보이도록 대각선 방향에서 촬영한다.
- 나를 구분할 수 있는 고정 단서를 둔다. 예: 파란 헤드기어와 검은 티셔츠.
- 상대의 영상과 음성을 외부 AI에 업로드하기 전에 동의를 받는다.

### 분석

```bash
cd /Users/kgw7401/atom
source .venv/bin/activate
export GEMINI_API_KEY="your-key"

python analyze_sparring.py /path/to/round.mp4 \
  --me "검은 티셔츠와 파란 헤드기어를 착용한 선수" \
  --context "상대 압박 뒤에 내가 멈추는 장면을 찾고 싶다"
```

### 검토

분석 결과의 각 장면에 대해 다음만 확인한다.

1. 모델이 지목한 시간이 실제로 의미 있는 공방인가?
2. 설명이 영상에서 보이는 사실과 맞는가?
3. 이 장면은 내가 느끼는 스파링 문제와 연결되는가?
4. 다음 라운드에서 시험할 규칙 하나로 줄일 수 있는가?

## 9. 성공 기준

첫 단계의 성공은 펀치 인식 정확도나 완전 자동화가 아니다.

- AI가 의미 없는 장면보다 중요한 의사결정 장면을 더 자주 찾아낸다.
- 나는 타임스탬프와 근거를 보고 결과를 빠르게 검토할 수 있다.
- 반복되는 문제 하나를 과장 없이 정리할 수 있다.
- 다음 라운드에서 행동 규칙 하나를 실제로 시도한다.
- 여러 라운드를 거치며 그 규칙의 실행과 실패 양상이 기록된다.

이 기준을 만족하면 이 시스템은 개인 훈련에 실질적인 가치를 만든다.

## 10. 지금 하지 않는 것

- 다른 사용자를 위한 서비스, 결제, 대시보드, 온보딩 설계
- 처음부터 데이터셋을 구축하고 복싱 이벤트 모델을 학습하는 일
- 한 영상으로 명중률, 승패, 전술 수준을 자동 판정하는 일
- VLM의 설명을 검증 없이 코칭 정답으로 받아들이는 일
- 샌드백/셰도우의 폼 교정과 스파링 의사결정 문제를 하나의 모델로 섞는 일

## 11. 연구로 이어지는 경로

연구는 서비스와 경쟁하는 별도 목표가 아니라, 반복 실험에서 발견한 한계를 푸는 단계다.

```text
개인 스파링 분석
  -> 실제로 도움이 안 되는 장면 또는 반복되는 모델 실패 기록
  -> 명확한 기술 문제 정의
  -> 이벤트 모델, 포즈 지표, 시간적 추론, 데이터셋 연구
  -> 다시 개인 분석 품질 개선
```

예를 들어 일반 VLM이 거리 변화나 방어 후 선택을 반복해서 잘못 이해한다면, 그 실패가 "복싱 거리와 시간적 의사결정 표현을 어떻게 보강할 것인가"라는 연구 문제가 된다.

장기 하이브리드 구조와 세부 액션 인식 방향은 [boxing-action-recognition-spec.md](boxing-action-recognition-spec.md)를 따른다. 이 문서는 그 기술 명세보다 한 단계 앞에서, 무엇을 먼저 검증하고 왜 하는지를 정의한다.

## 12. 의사결정 기록

- 시작점은 개인 프로젝트다.
- 1차 대상은 스파링 의사결정이다.
- 첫 기술 선택은 Gemini Files API를 이용한 VLM-first 분석이다.
- 출력은 자유 형식 조언이 아니라 검토 가능한 구조화된 관찰 기록이다.
- 피드백은 매번 하나의 다음 라운드 규칙으로 제한한다.
- 제품화와 연구 주제는 이 반복 과정에서 확인된 실제 문제를 바탕으로 결정한다.
