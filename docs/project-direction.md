# 프로젝트 방향: 개인 AI 복싱 코치

## 1. 한 문장 목표

복싱 스파링 영상을 AI가 분석해, 내가 경기를 어떻게 풀어나가면 되는지와 다음에 무엇을 훈련하면 되는지를 검증 가능한 근거와 함께 조언하는 개인 AI 복싱 코치를 만든다.

현재 첫 사용자는 나 자신이다. 서비스 출시, 사용자 확보, 논문 출판은 완료 조건이 아니다.

## 2. 코치의 작동 방식

코치의 산출물은 두 가지다.

- 경기 운영 조언: 거리 관리, 공수 밸런스, 링 포지션, 압박 대응 등 경기 전반에서 내가 무엇을 보고 어떤 선택을 했는지 진단하고, 다음 라운드를 어떻게 풀어나갈지 제안한다.
- 훈련 처방: 진단된 문제를 교정하기 위해 다음 훈련에서 무엇을 연습할지 제안한다.

단, 좋은 코치는 한 번에 모든 것을 고치지 않는다. 이 코치의 방법론은 다음과 같다.

> 전체를 보되, 한 번에 하나를 처방한다.

렌즈는 넓게 경기 전반을 관찰하고, 처방은 라운드당 최우선 문제 1개, 행동 규칙 1개, 훈련 메뉴 1~2개로 좁힌다.

## 3. 해결하려는 문제

샌드백이나 셰도우에서 기술을 수행하지 못하는 문제가 아니라, 스파링에서 내 경기 운영을 객관적으로 봐주고 구체적인 다음 행동으로 연결해 줄 코치의 눈이 없다는 문제를 다룬다. 특히 상대의 압박, 거리, 타이밍 앞에서 판단이 늦어지거나 멈추는 장면이 첫 관심사다.

첫 검증 질문은 다음과 같다.

> AI가 스파링 영상에서 내가 실제로 판단을 놓친 장면을 시간 근거와 함께 찾아내고, 다음 라운드에서 시험할 수 있는 피드백으로 만들 수 있는가?

이 질문에 답하기 전에는 완전한 복싱 분석 모델, 자동 채점 시스템, 서비스 UI를 만들지 않는다.

## 4. 현재 가설: 첫 번째 교정 포인트 후보

초기 영상에서 다음 후보 패턴이 발견됐다. 코치가 다루는 전체 범위가 아니라 첫 번째 교정 포인트 후보이며, 이후 스파링에서 검증할 가설이다.

```text
상대의 전진 압박
  -> 나는 방어하거나 직선으로 물러남
  -> 옆으로 빠지기, 반격, 클린치 같은 다음 선택이 늦어짐
  -> 로프 또는 코너에 갇히거나 수세가 길어짐
```

검증할 행동 규칙의 예시는 다음과 같다.

> 상대가 압박하며 들어오면 직선으로 계속 후퇴하지 않고, 비어 있는 쪽으로 한 번 피벗 또는 사이드스텝한다.

이 규칙이 이상적인 기술인지보다 내가 실제 라운드에서 기억하고 실행할 수 있는지가 먼저다.

## 5. 반복 루프

```text
스파링 한 라운드 촬영
  -> 의미 있는 공방과 후보 문제를 시간순으로 추출
  -> 내가 원본 영상으로 근거와 타임스탬프를 확인
  -> 최우선 문제 하나와 다음 라운드 규칙 하나를 선택
  -> 문제에 연결된 훈련 메뉴 1~2개를 처방
  -> 다음 훈련과 스파링에서 실행
  -> 실행 여부와 새로운 문제 장면을 다시 분석
```

좋은 결과물은 긴 코칭 리포트가 아니다. 다음 네 가지가 남으면 된다.

- 확인 가능한 타임스탬프와 시각적 근거가 달린 경기 전반 관찰 요약
- 최우선 문제(반복되는 의사결정·운영 패턴) 하나
- 다음 라운드에서 시험할 짧고 관찰 가능한 행동 규칙 하나
- 그 문제를 연습으로 연결하는 훈련 메뉴 1~2개

## 6. 분석 범위

샌드백/셰도우와 스파링을 하나의 문제로 취급하지 않는다.

| 모드 | 주된 질문 | 초기 피드백 단위 |
| --- | --- | --- |
| 스파링 | 상대를 보고 어떤 판단을 했고, 경기를 어떻게 운영했는가? | 압박, 거리, 방어 뒤 선택, 탈출, 카운터 기회 |
| 샌드백/셰도우 | 계획한 기술을 어떻게 수행했는가? | 자세, 균형, 연계, 반복, 리듬 |

첫 구현과 실험의 중심은 **스파링 모드**다. 드릴 모드는 코치의 훈련 처방을 실행하고 확인하는 채널로 나중에 붙인다. 초기에는 훈련 메뉴를 처방만 하고, 드릴 영상 자동 분석은 하지 않는다.

## 7. 범위 경계

코치라는 방향이 범위 폭발로 이어지지 않도록 세 축에 경계선을 둔다.

| 축 | 폭발 위험 | 경계선 |
| --- | --- | --- |
| 관찰 | 모든 기술·방어·채점을 한 번에 보려는 것 | 단계별 검증 로드맵을 따른다. 코치는 관찰 근거가 있는 것만 말하고, 없는 것은 침묵하거나 불확실로 표시한다 |
| 조언 | 경기 운영의 모든 영역을 한 번에 다루는 것 | 전체를 관찰하되 라운드당 최우선 문제 1개만 처방한다 |
| 훈련 처방 | 드릴 영상 분석과 방대한 드릴 라이브러리 구축 | 처방은 관찰된 문제에 연결된 지식 기반 제안으로 제한한다. 실행 확인은 내가 체육관에서 한다 |

관찰 확장은 수요 주도로 한다.

> 관찰 클래스는 코치가 말하고 싶은데 근거가 없는 것이 생길 때만 추가한다.

예를 들어 코치 리포트에서 잽 사용 빈도를 말하고 싶은데 펀치 검출이 없다면, 그것이 다음 관찰 단계의 우선순위가 된다. 미리 모든 클래스를 만들지 않는다.

## 8. 현재 기술 전략: Motion/Event-First

범용 VLM이 전체 영상에서 빠른 펀치와 회피를 안정적으로 판정할 것이라고 가정하지 않는다. 영상에서 검증 가능한 구조화된 사건을 먼저 만들고, 그 위에서 상황과 의사결정을 해석한다.

```text
영상
  -> 선수 탐지와 ID 추적
  -> 포즈/모션과 상대적 위치
  -> 펀치, 방어, 풋워크 이벤트
  -> 거리, 압박, 링 위치 상태
  -> 상대 행동 -> 나의 반응 -> 결과
  -> 반복 패턴 -> 다음 라운드 규칙과 훈련 처방
```

기술적 출발점은 BoxMind의 계층 구조다.

```text
atomic event -> tactical indicator -> strategy
```

BoxMind 전체를 복제하지는 않는다. 승률 예측과 엘리트 상대 전략 대신, 개인 스파링 코칭에 필요한 사건과 상태만 구현한다.

## 9. BoxingWeb의 역할

로컬 `~/boxingweb`에는 BoxMind 저자들이 공개한 공식 BoxingWeb 데이터셋과 동일한 구성이 있다.

- 전체 경기 영상 50개: train 40, test 10
- 유효한 펀치 이벤트 6,872개: train 5,537, test 1,335
- 시작/종료 프레임과 공격 선수
- 좌우 스트레이트, 훅, 어퍼컷
- 거리, 표적, effective/ineffective 속성
- 사전 추출된 선수 포즈 데이터

이 데이터로 먼저 펀치 이벤트 표현과 속성 분류를 재현한다. 다만 데이터에는 방어, 풋워크, 링 위치, 압박과 반응 관계가 충분히 라벨링되어 있지 않으므로 이후 개인 스파링 데이터로 그 계층을 보강해야 한다.

## 10. 언어 모델의 역할

VLM/LLM은 관찰의 단일 진실 공급원이 아니다.

가능한 역할은 다음으로 제한한다.

- 구조화된 이벤트와 상태를 사람이 읽기 쉬운 코치 언어로 변환
- 확신도가 낮은 장면의 보조 검토
- 여러 라운드의 기록 요약
- 근거가 연결된 다음 라운드 규칙과 훈련 메뉴 표현

펀치, 회피, 거리와 선후관계의 사실 판정은 전용 CV와 시간 모델이 담당한다. 언어 모델이 사용되더라도 출력은 항상 원본 타임스탬프와 하위 이벤트로 역추적할 수 있어야 한다.

## 11. 단계별 검증

### 단계 1: 펀치 속성 분류 재현

정답 구간이 주어졌을 때 공격 손, 기술, 거리, 표적, 효과를 분류한다. 공식 train/test 분할로 재현 가능한 기준선을 확보한다.

### 단계 2: 전체 영상 펀치 이벤트 검출

정답 구간 없이 전체 라운드에서 펀치 시작과 종료를 찾는다. 거짓 양성과 누락을 포함한 시간적 검출 성능을 측정한다.

### 단계 3: 상대적 모션 상태

두 선수의 거리 변화, 전진/후퇴, 측면 이동, 로프·코너 근접을 프레임별 상태로 만든다.

### 단계 4: 방어와 풋워크

개인 스파링에서 필요한 최소 클래스만 추가한다. 예: 블록, 슬립, 덕킹, 린백, 백스텝, 사이드스텝, 피벗, 클린치.

### 단계 5: 의사결정 패턴

`상대 행동 -> 나의 선택 -> 결과` 시퀀스를 만들고, 같은 실패가 반복되는 타임스탬프를 찾는다. 그때 처음으로 다음 라운드 규칙과 훈련 처방을 생성한다.

세부 구현과 중단 기준은 [BoxMind 재현 계획](boxmind-baseline-plan.md)에 기록한다.

## 12. 성공 기준

최종 성공은 펀치 분류 정확도 하나로 결정하지 않는다.

- 중요한 의사결정·운영 장면이 확인 가능한 타임스탬프로 제시된다.
- 장면 설명이 하위 이벤트와 모션 근거로 역추적된다.
- 반복되는 문제 하나를 과장 없이 정리할 수 있다.
- 다음 라운드 규칙 하나와 훈련 메뉴를 실제로 시도할 수 있다.
- 여러 라운드에 걸쳐 규칙의 실행과 실패 양상이 기록된다.

각 하위 모델은 별도 정확도와 오류 분석을 갖지만, 프로젝트 가치는 이 코칭 루프가 개인 훈련에 도움이 되는지로 판단한다.

## 13. 지금 하지 않는 것

- 다른 사용자를 위한 서비스, 결제, 대시보드, 온보딩 설계
- 경기 승률 예측이나 자동 채점
- BoxMind의 18개 전술 지표 전체 복제
- 모든 복싱 기술을 한 번에 라벨링
- VLM 설명을 검증 없이 코칭 정답으로 사용
- 샌드백/셰도우 폼 교정과 스파링 의사결정을 한 모델로 혼합
- 드릴 영상 자동 분석과 드릴 라이브러리 백과사전화

## 14. 의사결정 기록

- 시작점과 첫 사용자는 개인 스파링 훈련이다.
- 첫 실험은 Gemini 기반 VLM-first 분석이었다.
- VLM은 큰 흐름을 일부 포착했지만 빠른 펀치, 회피 방식과 선후관계를 불안정하게 판단했다.
- 반복 프롬프트와 느린 클립도 세부 사건의 신뢰도를 충분히 높이지 못했다.
- 따라서 2026-07-13 기술 전략을 `VLM-first`에서 `motion/event-first, language-last`로 변경했다.
- BoxMind의 계층 구조와 공식 BoxingWeb 데이터를 초기 기술 기준선으로 사용한다.
- 2026-07-14 프로젝트 지향점을 "압박 의사결정 분석"에서 "개인 AI 복싱 코치"로 확장했다. 코치는 경기 운영 조언과 훈련 처방을 제공하며, 압박 가설은 첫 번째 교정 포인트 사례가 된다.
- 같은 날 범위 폭발을 막기 위해 "전체를 보되 한 번에 하나를 처방"과 수요 주도 관찰 확장 원칙을 채택했다. 기술 전략과 단계별 검증 로드맵은 변경하지 않았다.

실험 근거는 [실험 기록](experiment-history.md)에 보존한다.
