## 1. 전체 흐름

```
스파링 영상
    │
    ├─[track_boxers.py]──────► tracks.csv     프레임별 두 선수의 화면 좌표
    │                                          (발, 어깨, 손목, 상의 밝기)
    │
    ├─[calibrate_ring.py]────► ground.json    카메라 보정값
    │                                          (초점거리, 지평선, 카메라 높이, 링 경계)
    │
    ├─[make_positions.py]────► positions.csv  프레임별 바닥 좌표 (미터)
    │                                          (위치, 정면, 사거리, 거리, 신뢰도)
    │
    ├─[make_stats.py]────────► stats.md       라운드 요약 수치
    │
    └─[make_topdown.py]──────► topdown.mp4    눈으로 검증할 영상
```

원칙 하나가 전체를 관통한다. **못 믿는 값은 지어내지 않고 못 믿는다고 적는다.**
모든 단계가 신뢰도를 같이 내보내고, 아래 단계는 그걸 보고 거른다.

## 2. 영상에서 직접 재는 것

`track_boxers.py` — YOLO 자세 모델(`yolo26n-pose`)로 프레임마다.

| 값 | 어떻게 | 쓰이는 곳 |
|---|---|---|
| 발 위치 | 양 발목 키포인트의 중점. 없으면 박스 아랫변 | 바닥 위치 |
| 어깨 좌우 | 어깨 키포인트 2개 | 정면 방향 |
| 손목 좌우 | 손목 키포인트 2개 | 사거리 반경 |
| 상의 밝기 | 몸통 영역의 median L* (CIELAB) | 누가 누구인지 |
| 박스 겹침 | 두 사람 박스의 IoU | 신뢰도 |

### 누가 누구인지 — 색으로 판단한다

YOLO 추적 ID 를 쓰지 않는다. 실제 영상에서 **두 선수 모두 트랙이 중간에 끊겨
새 ID 를 받았다** (1→14, 3→47). 그것만 믿으면 두 명 동시 검출이 53.6% 였다.

대신 상의 밝기로 매 프레임 독립 판단한다. 흰 상의 143~206, 검정 8~26 으로
격차가 크다. 이러면 ID 가 끊겨도 상관없다.

| 판단 근거 | IMG_0711 | IMG_0574 |
|---|---:|---:|
| 두 사람 밝기 비교 | 88.0% | 92.4% |
| 한 명만 보여 절대 밝기로 | 7.4% | 5.0% |
| 색을 못 믿어 직전 위치로 | 4.6% | 2.6% |

### 걸러내는 것 세 가지

- **링 밖 사람** — 발이 `ring_polygon` 안에 없으면 후보에서 뺀다.
  실제로 링 옆에 서 있던 관원이 상대로 잡힌 적이 있다
- **순간이동** — 1/60초에 사람이 갈 수 없는 거리면 이어붙이지 않는다.
  그 프레임은 빈칸으로 남긴다 (지어내지 않는다)
- **겹침** — 두 박스가 많이 겹치면 검출 자체를 못 믿으므로 신뢰도를 깎는다

## 3. 카메라 보정 — 링을 자로 쓴다

`calibrate_ring.py`

사람 키만으로 바닥 평면을 추정하던 초기 방식은 **초점거리를 기종 명목값으로
가정해야 했고, 그게 틀렸다.** 줌으로 찍힌 영상이라 1x(24mm) 값이 안 맞았다.
그 결과 깊이가 절반 이하로 눌려 있었다.

지금은 링 자체를 쓴다. 가정할 게 없다.

```
선수를 지운 배경 (60장 중앙값)
    → 로프 선분 검출 (Hough)
    → RANSAC 으로 소실점 2개
    → 링이 정사각형 = 두 방향이 직각 → 초점거리
    → 두 소실점을 잇는 선 = 지평선
    → 사람 키로 카메라 높이
```

| | IMG_0711 | IMG_0574 |
|---|---:|---:|
| 초점거리 | 2249 px (42mm 환산) | 4757 px (45mm) |
| 지평선 y | 74 | 190 |
| **카메라 높이** | **2.12 m** | **2.20 m** |

**카메라 높이가 서로 다른 영상에서 8cm 차이로 나온 것**이 가장 강한 검증이다.
같은 삼각대이고, 두 값은 독립적으로 구했다.

초점거리도 교차검증했다. 두 선수가 화면에서 좌우로 벌어져 있을 때의 거리는
초점거리와 무관하고, 앞뒤로 벌어져 있을 때는 비례한다. 복서는 카메라 방향과
무관하게 비슷한 거리를 유지하므로 **두 경우가 일치하는 초점거리**가 정답이다.
그 값이 **2200** — 소실점으로 구한 2249 와 2% 차이다.

## 4. 바닥 좌표로 바꾸기

`make_positions.py` — 화면 좌표를 미터 단위 바닥 좌표로.

```
깊이  Z = f · h / (화면y − 지평선y)
좌우  X = (화면x − 중심) · h / (화면y − 지평선y)
```

### 발목 높이 보정

발목 키포인트는 지면이 아니라 **발목 관절**이다. 성인 키의 5% 위(약 9cm)에 있는데,
그대로 바닥에 투영하면 카메라 반대쪽으로 밀린다. 7m 거리에서 30cm 가 넘는다.
카메라 높이를 `(실제 높이 − 발목 높이)` 로 낮춰 투영해 고쳤다.

발견 경위: 링 경계와 겹쳐 보니 선수가 캔버스 밖 39cm 까지 나가 있었다.
물리적으로 불가능하므로 체계적 오차였다.

### 정면 방향

두 어깨는 같은 높이에 있으므로, 각 어깨의 깊이를 따로 구해 방향을 만든다.
어깨 높이는 계산에서 약분되므로 **키를 몰라도 된다.**

시계열 처리를 두 갈래로 나눈다. 하나로 묶으면 서로를 망친다.

- **축(기울기)** — 각도를 2배로 만들어 평균하고 이어붙인 뒤 절반으로 되돌린다
- **부호(앞/뒤)** — 주변 창의 다수결. 자세 모델의 좌우 어깨 라벨에서 나온다

### 사거리 반경

발 중심에서 손목까지의 **좌우 거리**, 영상 전체의 98% 분위수.
좌우 성분만 쓰는 이유는 세로 거리에는 손 높이가 섞이기 때문이다.

### 신뢰도

아래를 곱해서 만든다.

| 요인 | 감점 |
|---|---|
| 정체를 색으로 판단 / 절대 밝기 / 직전 위치 | ×1.0 / ×0.85 / ×0.4 |
| 발 위치가 양발목 / 한발목 / 박스 | ×1.0 / ×0.85 / ×0.6 |
| 발이 화면 밖으로 잘림 | ×0.5 |
| 박스 겹침 0.15 이상 / 0.35 이상 | ×0.7 / ×0.25 |

거리가 0.3m 미만이면 물리적으로 불가능하므로 값을 버린다.

### 결과

| | IMG_0711 | IMG_0574 |
|---|---:|---:|
| 거리가 나온 프레임 | 88.3% | 90.7% |
| 그중 신뢰도 0.6 이상 | 80.9% | 82.8% |

## 5. 스탯 — 무엇을 어떻게 뽑나

`make_stats.py`. 신뢰도 0.6 미만은 계산에서 뺀다.

### 거리

| 스탯 | 계산 |
|---|---|
| 분포 | 중앙값, 사분위, 표준편차 |
| 사거리 관계 | 두 사람의 사거리 원이 상대 **몸**(반경 0.22m)에 닿는지로 4분할 |

사거리 관계는 아직 확정값을 못 낸다. 지금 사거리는 발을 안 옮기고 잰 것인데
실제 펀치는 스텝을 밟기 때문이다. **여유값을 바꿔가며 감도표**로만 낸다.

### 움직임 — 주도권 분해

**이번 작업에서 가장 쓸모 있는 정의다.**

두 사람의 속도를 서로를 잇는 축에 투영하면 거리 변화가 이렇게 쪼개진다.

```
거리 변화율 = −( 내가 상대 쪽으로 간 속도 + 상대가 내 쪽으로 온 속도 )
```

그러면 "누가 거리를 정하는가" 가 인상이 아니라 숫자가 된다.

| 스탯 | 계산 |
|---|---|
| 좁힐 때 주도 | 거리가 줄어든 프레임 중, 내 기여가 더 큰 비율 |
| 벌릴 때 주도 | 거리가 늘어난 프레임 중, 내가 더 물러난 비율 |
| 전진 시간 | 내 속도의 상대 방향 성분이 양수인 시간 비율 |

속도는 ±3프레임 중앙차분. 6 m/s 를 넘으면 추적이 튄 것으로 보고 버린다.

### 각도

| 스탯 | 계산 |
|---|---|
| 정면 벗어난 각 | 정면 방향과 상대 방향의 차이 |
| 각도 우위 시간 | 내 벗어난 각이 상대보다 작은 시간 비율 |
| 피벗 | 0.3초 안에 45도 이상 회전. 한 번 세면 0.4초 쉼 |

**신뢰도 0.3 이상 프레임만 쓴다** (아래 문제 참고).

## 7. 지금 있는 문제

우선순위 순.

### ① 각도를 못 잰다 — 프레임의 3%

**원인은 기하학적 한계이지 버그가 아니다.** 어깨선이 화면에서 수평에 가까우면
3차원 방향이 원래 결정되지 않는데, 이 카메라 각도에서는 **71% 의 프레임이 그렇다**
(신뢰도 중앙값 0.10). 카메라가 링을 얕게 내려다보고 복서 어깨는 대체로 수평이다.

신뢰도로 거르면 값은 좋아지지만(오차 33도→26도, 90도내 90%→96%) 남는 프레임이
20% 이고, **두 선수가 동시에 신뢰할 만한 것은 3%** 다. 99초 중 3초다.

> 이 과정에서 두 번 틀렸다. 처음엔 지표를 잘못 봤다 (프레임당 변화 1.3도만 보고
> 좋다고 판단, 실제로는 방향 전환이 초당 7~10회). 다음엔 원인을 잘못 짚었다
> (식이 발산한다고 보고 바꿨는데 두 식이 같은 값이었다 — 차이 중앙값 0.0000도).

**해결책은 촬영이다.** 카메라를 더 높이 올릴수록 어깨선이 화면에서 기울어진다.

### ② 링 크기가 영상마다 다르다

같은 링인데 방법을 바꿀 때마다 값이 바뀐다.

| 시도 | IMG_0711 | IMG_0574 |
|---|---:|---:|
| 고정 색 기준 | 3.91 m | 3.37 m |
| 발 위치로 색 자동 맞춤 | 3.94 m | 3.70 m |
| + 선수 범위로 제한 | 3.94 m | 4.26 m |
| + 발이 닿은 덩어리만 | 3.63 m | 3.23 m |

캔버스 색이 영상마다 다르고, 어떤 영상은 링 밖 바닥과 색이 거의 같고, 로프가
캔버스를 가로로 가른다. 네 번 시도해서 네 번 다 흔들려 멈췄다.

**단, 거리 측정에는 영향이 없다.** 거리는 초점거리·지평선·카메라 높이에서 나오고
그건 교차검증됐다. 링 크기는 top-down 에 테두리를 그릴 때만 쓴다.

**다음 시도**: 색 대신 **로프**를 쓴다. 대비가 뚜렷하고 절대 안 가려지며 이미
소실점 때문에 검출하고 있다. 링 경계는 로프 바로 아래다.

### ③ 사거리 반경이 영상 길이에 좌우된다

같은 사람인데 0.65 m (IMG_0711, 표본 3924) vs 0.53 m (IMG_0574, 표본 912).
98% 분위수를 쓰는데 짧은 영상에서는 팔을 최대로 뻗은 순간이 안 잡힌다.

**영상 길이에 따라 달라지는 정의는 정의가 아니다.** 2단계(펀치 이벤트)에서
실제로 닿은 거리로 정하는 것이 옳다.

### ④ 거리 5단계를 못 나눈다

두 가지가 겹쳤다.

- 밀착 경계 0.65m 는 **틀린 보정 위에서** 사진을 보고 정한 값이라 무효가 됐다
- **한 발 사거리**가 없다. 정지 사거리만으로는 99% 가 "둘 다 못 닿음" 으로 나온다

primer 의 정의가 이미 그렇게 말한다 — "엣지 오브 레인지 = **한 발 들어가면** 닿는 경계".
원이 몸 / 정지 사거리 / **한 발 사거리** 세 개여야 한다.

### ⑤ 데이터가 라운드 2개뿐이다

지금 나온 결론들은 전부 한 라운드짜리다. "뒷발 성향" 도 IMG_0711 에서만이고
IMG_0574 는 대등하다. **성향인지 그날인지 상대 탓인지 구분할 수 없다.**
